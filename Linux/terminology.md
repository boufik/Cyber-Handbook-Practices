**ABI — Application Binary Interface.** The binary-level contract between compiled components: which register holds which argument, how structs are laid out, what a syscall number means. Linux guarantees a stable *userspace* ABI (a binary from 2005 still runs today), but deliberately offers **no stable in-kernel ABI** — internal function signatures and struct layouts change freely between versions, which is why an out-of-tree module like the NVIDIA driver must be rebuilt for every kernel (that's what DKMS automates).

**Address space.** The range of virtual addresses a piece of code can reference, translated to physical RAM by the MMU using per-process page tables. Each process gets its own, so `0x7fff...` in Firefox and `0x7fff...` in your shell point to entirely different physical memory. On x86_64 the split is conventionally 128 TB user / 128 TB kernel.

**Blob — binary large object.** In kernel context, a vendor-supplied firmware image shipped as compiled bytes with no source, which the kernel uploads into a device at probe time. Example: `/lib/firmware/iwlwifi-*.ucode`, pushed into an Intel Wi-Fi card before it will work. Distros like Debian separate these into a `firmware-nonfree` package because they aren't free software.

**cgroup — control group.** A kernel mechanism for accounting and limiting resources (CPU shares, memory ceiling, block I/O bandwidth, PID count) across a group of processes. Exposed as a filesystem: writing `500M` to `/sys/fs/cgroup/mygroup/memory.max` caps that group, and exceeding it triggers the OOM killer inside the group only. systemd puts every service in its own cgroup; so does every container runtime.

**Decompressor stub.** `vmlinuz` is mostly a compressed payload (gzip, LZ4, zstd), so a small uncompressed piece of real-mode/early code is prepended to it. The bootloader jumps to that stub, it inflates the actual kernel into memory, and jumps to the entry point. It exists because the kernel can't decompress itself before it exists in memory.

**Hook.** A predefined call site where the kernel invokes registered callback functions, letting subsystems inject logic without patching core code. **LSM (Linux Security Modules)** hooks sit at security decision points — e.g. `security_file_open()` fires on every open, and SELinux or AppArmor's registered function there returns allow or `-EACCES`. eBPF, netfilter, and kprobes all work the same way: a fixed attach point plus a callback.

**IRQ handler — Interrupt ReQuest handler.** The function the kernel runs when a device raises an interrupt line, e.g. a NIC signalling that a packet arrived. It runs in interrupt context with tight constraints (can't sleep, can't allocate freely), so it does the minimum — acknowledge the device, grab the data — and defers the real work to a softirq or workqueue. `cat /proc/interrupts` shows the counts per IRQ per CPU.

**Kernel build.** The artifact produced by compiling kernel source with a specific `.config` for a specific architecture: a `vmlinuz` image, a matching `System.map`, and a `/lib/modules/<version>/` tree of `.ko` files. Config choices are compile-time (`y` = built in, `m` = loadable module, `n` = absent), so a Debian generic kernel and a hardened custom build from identical source are different binaries with different capabilities.

**Kernel space.** The portion of the virtual address space mapped only when the CPU is at high privilege, containing kernel code, its data structures, and its allocations. All of it is shared — there is one kernel address space, not one per process. A bad pointer dereference here produces an oops or panic rather than a segfault, because there's no outer layer to catch it.

**libc — the C standard library.** The userspace library implementing `printf`, `malloc`, `open`, `fopen` and so on; on Linux typically **glibc** (GNU) or **musl** (small, used by Alpine). It's the usual wrapper around syscalls: your `read()` call enters glibc, which sets up registers and executes the actual `syscall` instruction. The kernel itself does *not* link against libc — it has its own internal equivalents (`printk`, `kmalloc`), which is why kernel C looks foreign.

**Namespace.** A kernel feature that gives a set of processes a private instance of an otherwise global resource, so they see a different view of the system. Example: inside a `net` namespace, `ip addr` shows only that namespace's interfaces and its own port 80 is separate from the host's. Eight types exist (`mnt`, `uts`, `ipc`, `pid`, `net`, `user`, `cgroup`, `time`); `lsns` lists them, `nsenter -t <pid> -n` drops you into one.

**Other "spaces."** Beyond user/kernel there's **hypervisor space** (ring −1 / EL2, where KVM or Hyper-V runs beneath a guest kernel), **SMM — System Management Mode** on x86 ("ring −2"), a firmware mode the OS cannot see or intercept, and **secure world** (ARM TrustZone / EL3, where a TEE runs). Each sits *below* the kernel in privilege, which is why firmware-level implants are so hard to detect from the OS.

**Privilege.** Two distinct meanings that get conflated: *CPU privilege* (which ring you execute in, enforced by hardware) and *OS privilege* (what your UID and capabilities let you ask the kernel to do). `sudo` only affects the second — it's a setuid-root userspace binary that checks `/etc/sudoers` and then executes your command with UID 0. A sudo'd process is still ring 3 and still makes ordinary syscalls.

**Rings 0–3.** x86 hardware privilege levels, where lower is more privileged; it's a strict hierarchy, not a precedence list. Ring 0 may execute privileged instructions (`lgdt`, `wrmsr`, page table writes) and access any memory; ring 3 attempting these takes a #GP fault. Rings 1 and 2 are unused by mainstream OSes; ARM's equivalent is EL0/EL1/EL2/EL3.

**Ring 3 → ring 0.** Legitimately: only via hardware-defined entry points — the `syscall`/`svc` instruction, an interrupt, or an exception — each of which lands at a fixed kernel address chosen by the kernel, not by you. You never control *where* execution resumes, only which syscall number you asked for. Illegitimately: exploit a kernel bug reachable from userspace, or load your own code (a signed module, or an eBPF program that passes the verifier). This is exactly why root ≠ ring 0.

**Symlink — symbolic link.** A filesystem entry whose content is a path string, so opening it redirects to the target. `/proc/self/ns/net` is a symlink whose target looks like `net:[4026531840]` — an identifier, not a real path — which is how you compare whether two processes share a namespace. Created with `ln -s`, inspected with `ls -l` or `readlink`.

**Syscall — system call.** The only sanctioned way userspace requests a kernel service: put a number and arguments in registers, execute `syscall`, and the CPU transitions to ring 0 at a fixed handler. `openat` is number 257 on x86_64; `strace ls` shows the full sequence a program makes. There are roughly 350–450 of them depending on architecture, and this boundary is where seccomp filtering and most host-based detection sits.

**UID / GID checks.** UID = user ID, GID = group ID; the kernel stores these per process and compares them against file ownership and permission bits on every access. **UID 0 is root**, which historically bypasses those checks entirely (modern kernels decompose this into ~40 capabilities like `CAP_NET_ADMIN`). **UID 1000** is conventionally the first regular human account created at install; system daemons get low UIDs (1–999) by convention, not by kernel rule.

**Userspace.** Everything running at ring 3 in its own address space: your shell, systemd, sshd, browsers, plus libraries like glibc. On the Venn question — it's not quite two halves of one circle. "Linux" strictly names the kernel; a *distribution* is kernel + userspace, so `OS = kernel + userspace` holds for the colloquial sense of "operating system," while the kernel/userspace split itself is a privilege boundary rather than a partition of one product.
